# 独立洪水漫灌导航模块

本目录是尚未接入固件的纯 C11 组件。仅使用标准头文件，不包含 HAL、
FreeRTOS 或任何现有工程头文件；不创建任务、不访问外设、不执行 I/O、
不分配动态内存。所有外部符号使用 `flood_nav_` 前缀，内部数据均为静态私有。

现有 `.cproject` 的 Debug/Release source entries 仅包含 Core、Drivers、
Middlewares，因此 navigation 不进入当前固件构建。不要把本目录或 tests
加入固件 source entries，除非未来明确开始接入；测试文件有独立的 main。

## 配置与坐标

- 行列数可分别配置为 1～32，支持长方形地图。32×32 是静态容量上限，
  不是运行时固定地图大小；修改上限需要重新验证内存与测试。
- 单格为正方形，`cell_mm` 范围 1～65535 mm。
- 起点和终点使用 `(col, row)`，左上角 `(1,1)`，列向右增加，行向下增加。
- 上北、下南、左西、右东。枚举顺序为 N、E、S、W。
- `initial_heading` 是上电时车头在地图中的实际方向。
- 输出 `east_mm` 向右/东为正，`north_mm` 向上/北为正，原点是起始格中心。
  两个坐标均使用 int32_t，避免大地图或大单格时溢出。
- 终点行为固定为“到目标格中心且车轮停稳后完成”，无需重复传停止模式。

这里输出的是地图坐标，不是当前固件的开机车体坐标。以后适配时必须根据初始
朝向做旋转，并处理实际起始位置与格中心的偏差；不能直接强转为现有 int16_t
路点。模块不会修改现有 pose，也不做坐标系的隐式猜测。

## 四个公共函数

| 函数 | 用途 |
|---|---|
| `flood_nav_init(config)` | 校验配置，清空内部地图，外围自动设墙，内部设未知；再次调用即复位 |
| `flood_nav_observe(cell, direction, edge)` | 提交一条已确认的地图绝对方向边，自动同步邻格反向边 |
| `flood_nav_set_location(location)` | 输入当前格、实际朝向、是否在格中心、是否停稳 |
| `flood_nav_next(out)` | 重算距离场并返回一步候选、等待原因、无路或完成 |

配置错误时 init 不修改旧状态。初始化后必须显式输入有效位置，防止上电即
假定车辆已经处于格中心。observe 允许纠正内部墙体或恢复 UNKNOWN；外边界
禁止设为 OPEN/UNKNOWN。所有枚举、坐标和布尔输入均校验。

组件是单实例、非线程安全的。以后应由一个导航任务独占调用；不在 ISR 中调用。
本阶段不提供桥接层、雷达输入函数、任务代码或自动启动逻辑。

## 状态和调用顺序

```text
init
  ↓
set_location（真实格号、朝向、到中心与停稳确认）
  ↓
observe（提交新鲜且已确认的墙体/通路）
  ↓
next
  ├─ READY：允许执行返回的一个格中心目标
  ├─ NEED_OBSERVATION：仅返回待检查方向，禁止执行该候选
  ├─ NEED_LOCATION：等待有效位置输入
  ├─ WAIT_CENTER：等待到达当前格中心
  ├─ WAIT_STOP：等待车轮停稳
  ├─ NO_PATH：当前地图下无路，交给调用者停车/提示/等待新观测
  ├─ FINISHED：已经在终点中心且停稳
  └─ 负值：参数、初始化或边界错误
```

只有 READY 与 NEED_OBSERVATION 会写入输出；其余状态保持输出不变。
调用者必须先检查返回值，不能重用上一次候选继续开车。
重复调用 next 不推进车辆或格号，也不代表一次移动完成；到下一格后必须重新
set_location。只进入终点格不会返回 FINISHED，仍需中心与停稳条件。

简化调用示例（省略实际感知、运动和错误处理）：

```c
#include "flood_nav.h"

flood_nav_config_t config = {
    .cols = 6, .rows = 4, .cell_mm = 600,
    .start = {1, 4}, .goal = {6, 1},
    .initial_heading = FLOOD_NAV_NORTH
};
flood_nav_location_t location = {
    .cell = {1, 4}, .heading = FLOOD_NAV_NORTH,
    .at_center = 1, .stopped = 1
};
/* 每一个返回值都需要调用者处理。 */
flood_nav_result_t result = flood_nav_init(&config);
if (result == FLOOD_NAV_READY) {
    result = flood_nav_set_location(&location);
}
if (result == FLOOD_NAV_READY) {
    /* 实际程序先提交经过确认的新墙体/通路观测。 */
    flood_nav_step_t step;
    result = flood_nav_next(&step);
    if (result == FLOOD_NAV_NEED_OBSERVATION) {
        /* 请求观测 location.cell 的 step.direction；此时不行驶。 */
    } else if (result == FLOOD_NAV_READY) {
        /* 后续适配层执行 step；本组件不驱动车辆。 */
    }
}
```

## 算法及有界执行

从目标反向 BFS，UNKNOWN 可参与距离估计，WALL 不可通过。实际下一步只有
OPEN 才返回 READY。沿严格递减的距离选择下一格；距离相同优先当前朝向，
再按 N/E/S/W 保持确定性。地图不变时不会因访问惩罚偏离距离下降方向或循环。

BFS 每格最多入队一次。最大 1024 次出队、4096 次邻边检查，队列不会扩容，
无递归、无无限重试、无阻塞等待。地图相关工作数组共 8192 B，加少量配置和
位置状态；未加入固件构建时不占用现有固件 RAM/Flash。

动态揭墙时可以返回以前经过的格，这是重新探索，而非距离场内部循环。
如果未来适配层一直不给观测、格中心确认或停稳确认，组件会持续返回相应等待
状态；适配层应另设超时并报告原因，不能无限等待。MCU 上的执行耗时仍需接入
后实测，主机测试不等同于实时性证明。

## 感知及控制边界

### 已确认的车体与雷达几何

- 车体为圆形，直径 200 mm，半径 100 mm。
- 以车体圆心为原点，车头方向为前方，雷达沿前后轴位于圆心后方 45 mm，
  横向偏移为 0 mm。
- 以车体前向为正的安装偏移为 -45 mm；该偏移跟随车头旋转，不能固定当作
  地图南向偏移。雷达角度零偏与扫描正方向尚未标定。
- 若已知圆心地图坐标 C、车头地图单位向量 f，则雷达原点 L = C - 45*f。
  将雷达极坐标回波转入地图时，先按安装角和车头朝向旋转射线，再以 L
  为射线原点；不能直接以 C 为原点投射回波。
- 圆形车体的障碍膨胀半径为 100 mm 加额外安全余量；安全余量仍待确定。
  膨胀应以车体圆心轨迹为基准，不能简单要求各方向雷达距离都大于 100 mm。
  例如车头朝向的最前车壳距雷达 145 mm，正后方车壳距雷达 55 mm，
  这两个数仅为轴向几何距离，不代表制动阈值。
- 两驱动轮的轮轴中点与雷达位置重合，均位于圆形车体圆心后方 45 mm。
  现有位姿模块的参考点为轮轴中点，因此其位置 P 也是雷达原点 L。
  车体圆心 C = P + 45*f。建图直接以 P 投射雷达回波，不可再次扣除 45 mm；
  圆形车体碰撞检查则以 C 为中心，使用 100 mm 加安全余量的膨胀半径。
- 原地转向时轮轴中点/雷达可保持不动，但车体圆心会绕它旋转，半径为 45 mm。
  完整原地转向的车体扫掠包络，相对轮轴中点最大半径为 145 mm（再加安全
  余量）；不能仅用以雷达为中心的 100 mm 圆判断掉头空间。
- 模块的下一格输出只表达格中心目标，本身不规定车辆的哪个物理点到达该中心。
  建议未来适配层将“车体圆心到目标格中心”作为目标语义。若格中心为 G，
  预期到达朝向单位向量为 f_goal，则轮轴中点目标应为 P_goal = G - 45*f_goal。
  若起始车体圆心就在起始格中心、现有位姿在上电轮轴中点清零，则格中心
  输出 g（相对起始格中心）转换成该位姿坐标中的轮轴目标时，需使用
  P_goal = g + 45*f_start - 45*f_goal，其中所有向量先转到同一坐标系。
  到达后若再转向，需要重新考虑圆心偏移；不能沿用同一轮轴目标而假定圆心
  始终停在格中心。起始圆心不在格中心时，还需加入实际起始偏移。

上述参数记录供未来独立适配/感知层使用，当前纯格网规划接口不读取这些
参数，也不据此宣称已经完成车体碰撞检查。格网边长和墙体厚度需要结合
200 mm 车体直径及安全余量验证实际通行空间。

此版本封装地图、Flood Fill 和下一格中心输出；不移植仿真物理、VFH、连续
前瞻、雷达射线建图或显示。observe 接收的是已确认边状态，不是原始雷达距离。
雷达时间戳、有效期、重复回波去重、质量筛选、多次投票和车辆尺寸检查都属于
未来独立适配/感知层。OPEN 仅代表调用者报告可通行，组件本身不能保证物理安全。

实际接入前还需处理：初始格内定位、朝向旋转、扫描停稳、运动过程障碍停车、
急停优先级、取消控制任务手中的旧路点、目标中心容差和编码器停稳阈值。
地图观测改变后，调用者必须取消旧目标再应用新规划；模块不访问现有 Q_Path。

## 独立测试

Windows PowerShell（需要主机 GCC，而不是 arm-none-eabi-gcc）：

```powershell
& .\navigation\flood_nav\tests\run_tests.ps1
# 或指定编译器
& .\navigation\flood_nav\tests\run_tests.ps1 -Compiler 'D:\BaiduNetdiskDownload\MinGW\bin\gcc.exe'
```

脚本启用 C11、Wall、Wextra、Werror、Wpedantic、Wconversion、Wshadow。
所有可执行文件和日志写入系统临时目录，不在原工程生成编译产物。
测试进程超过 20 秒会被终止并报错，防止回归测试卡住。

覆盖配置拒绝与原状态保留、输出未写保护、全部四方向、1×1、窄地图、
非方形地图、未知边阻止执行、墙体双向同步与纠正、新墙重规划、中心/停稳
门控、100 张地图对独立参考 BFS、21 趟在线揭墙运行、32×32 全连通地图，
以及 1023 步蛇形通道（距离超过 255）和最大单格尺寸坐标。

可移植编译示例：

```sh
cc -std=c11 -Wall -Wextra -Werror -Wpedantic -Wconversion -Wshadow -O2 \
  -I navigation/flood_nav navigation/flood_nav/flood_nav.c \
  navigation/flood_nav/tests/test_flood_nav.c -o /tmp/test_flood_nav
/tmp/test_flood_nav
```
