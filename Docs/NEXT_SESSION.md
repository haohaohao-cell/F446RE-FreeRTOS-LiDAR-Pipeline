### 5.1 三个点位与路径形状（**以课件第 3 页原图为准**）

| 趟 | 蓝牙命令 | 路径 | 终点（世界系，mm） |
|---|---|---|---|
| 1 | `G 0 1400` | 沿 +y 直行 | (0, 1400) |
| 2 | `G -700 700` | 直行 700 → **左转 90°** → 直行 700 | (−700, 700) |
| 3 | `G 700 700` | 直行 700 → **右转 90°** → 直行 700 | (700, 700) |

**两处依据，别搞混**：

- 课件**正文**第 2 页写的是 `(0.70, −0.70)`，**第 3 页的图**画的是 `(0.70, 0.70)`
  （右臂，箭头从 (0.00,0.70) 指向 (0.70,0.70)）。两者矛盾，**取图**：
  正文那个负号是笔误，十字形场地没有"后方"这条臂（三条臂是正前/左前/右前）。
- 老师口头纠正的"**先走直线，再转弯**"也是图上的形状：旧代码是"一条直线到目标"，
  `|err| > 45°` 时先原地转，所以 (700,−700) 那趟会先右转 135° 再斜着走 —— 形状错了。

代码上由 `path_generate_manhattan()` 保证：**先走完 y 腿，再走 x 腿**，拐角 (x0,y1)
只发一次。`(0,1400)` 退化成单一 y 腿，航点与旧版逐点相同。

## 6. 现场踩过的坑（**都是修的，重写会复现**）

| # | 症状 | 根因 | 修法 |
|---|---|---|---|
| 1 | 双击快捷方式**闪退** | `.cmd` 是 LF 换行，cmd.exe 双击时解析失败 | 全部改成 CRLF |
| 2 | 车**原地转圈**（两轮反向） | 蓝牙**打开后的第一次写入被吞**，`Z` 丢了 → `G` 拿上一趟位姿跑 → 航向误差 >45° | `Z` 连发两次（`bt_run.ps1`），单字母命令也发两次 |
| 3 | `demo_2`（负坐标）报**参数错误** | `-File` 模式下 `-700` 被当参数名 | 改用 `-Command` 传字面量 |
| 4 | **命令发出去了，车不动**，人以为固件坏了 | `SerialPort.Open()` 成功 ≠ 无线链路通；端口是配过对的虚拟口，链路断了它照样能开 | 开完端口**读遥测字节**证明链路活着（`bt_common.ps1`），0 字节就拒绝发车 |
| 5 | 蓝牙蓝灯**一闪一闪**（不是常亮） | 常亮 = 已连接；闪 = 链路没建立/正重连。原因只有三类：车没上电、电池跌落、PC 适配器省电 | 见 §6.1 |

> 坑 2 与历史坑 E（晚到的 STOP 清掉新路径）是同一类：**SPP 写入不等于送达**。

### 6.1 蓝牙蓝灯一闪一闪怎么办（按代价从低到高）

| 顺序 | 动作 | 怎么算好了 |
|---|---|---|
| 1 | 确认**车已经上电**（模块是从车上取电的，不是 USB） | `preflight_link.cmd` 出 `link: OK` |
| 2 | 关掉占着 COM10 的程序（点云窗口 `pc_app`、被强杀的 bt_run 窗口） | 报错从 `already open elsewhere` 变成正常 |
| 3 | 电池**充满**（电机启动电流把 3.3 V 拉跌 → 模块复位 → 重连） | 起步不再顿挫；链路字节率稳定 |
| 4 | 设备管理器 → 蓝牙适配器 → 电源管理 → **取消**"允许计算机关闭此设备以节约电源" | 空闲 1 分钟后再发命令仍然 `link: OK` |
| 5 | 硬件：模块 VCC-GND 并 100–470 µF 电解；天线远离电机线 | 电机启动瞬间不再掉线 |

> 这五条都不改固件。第 4 条是 Windows 侧最常见的原因：SPP 链路空闲一段时间后
> 适配器被挂起，模块看到的是"对端走了"，于是回到闪灯重连状态。

### 6.2 万向轮后移 / 整车反向：只有一个开关

底盘改成"驱动轮在前、万向轮在后"（车身相对接线转了 180°）时，**只需要改一个常量**：

```c
/* Core/Inc/board_pins.h  §3b */
#define BOARD_DRIVE_FRAME_REVERSED 1   /* 0 = 原样（万向轮在前） */
```

改完 `make -C Debug -j8 all` + 烧录。开机横幅会打印实际生效的那一版：

```
[drive] frame: REVERSED (caster at rear)     <- 1
[drive] frame: normal (caster at front)      <- 0
```

**为什么只改这一处**：

| 会变 | 不变 |
|---|---|
| 左右轮对调：接线上的"左"轮现在在车的右边 | 航向偏置 `POSE_IMU_TO_NAV_DEG`（=90）**不用动** |
| 电机输出对调（`motor.c: apply_outputs`） | 正方向不取反 —— 正占空比仍然是"向前" |
| 编码器读入对调（`encoder.c: ch_logical_*`） | 里程换算、PID 增益、控制律全部不动 |

航向不用动的理由：航向是"陀螺开机零位 + 90°"，而操作者摆车时总是**让车的前进方向沿 +y**；
车体绕**竖直轴**转 180° 不改变陀螺对偏航角速度的读数。

**这个开关错了不是"精度差"，而是每个转弯都反** —— 航向闭环会朝远离路点的方向转。
所以：改机械 → 改常量 → 重新编译烧录 → **先看开机横幅** → 再上台架（轮子架空，`f`/`l`/`r` 看方向）。

> 这一版固件**没有在反向底盘上跑过**，属于【待实测】。开关在 `#if` 里，默认 0 时
> 生成的机器码与原版一致，不会影响现有演示。

## 11. 已知的物理限制（答辩要主动说）

1. **死区随负载升高**：空载 20–30% 不转；带载 40% 也推不动（实测左轮 4.8 s 走 2 mm，
   同一轮 100% 走 10508 counts）。所以低调试点动键在弱电池下不可用 → **必须充满电**
2. **转向段位移未建模**：见 §3 最后一段
3. **位姿不累积陀螺漂移**（航向直接赋陀螺值），但会继承陀螺零偏；上电后静止 1–2 s 再跑
4. **蓝牙是"命令单向、遥测连续"**：车不回 `G`/`S` 的应答（`A`/`E` 帧未实现），
   但 **UART5 一直在发 20 帧/s 的遥测**（`telemetry_send_data`）。所以"链路通不通"
   可以用**收到的字节数**客观判断 —— `tools\bt_link_check.cmd` 就是干这个的，
   正常约 7000 B/s。**0 B/s = 链路死了，别发车。**
